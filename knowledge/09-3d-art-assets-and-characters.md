# 09 — 3D Art, Assets & Characters

> Scope: how to **create, import, texture, optimize, source and upload** art assets for an original Roblox game, plus characters/NPCs/avatars and 2D UI art. Lighting, atmosphere and level composition are covered in another chapter; this one is about the *things* you put in the world.
>
> Verified against the official Creator Docs snapshot (`reference/creator-docs/content/en-us`) and DevForum announcements as of 2026-11-05. Where docs disagree with each other, both are noted. Treat anything marked *(verify)* as something to re-check in Studio before relying on it.

---

## TL;DR rules for the bot

1. **1 Blender unit = 1 stud.** Set Blender *Scene ▸ Units ▸ Unit System = None*. Export **glTF/GLB** when you can (no scale surprises); if FBX, use *Apply Scalings = FBX Unit Scale* and leave every other scale at 1.0.
2. **Apply transforms before export** (Ctrl+A ▸ All Transforms, or `transform_apply` in bpy). Put the origin where the object should pivot (bottom-center for props that sit on the ground). Name every object; names become `MeshPart` names.
3. **Hard limits:** ≤ **20,000 triangles per mesh** (imported MeshPart, CSG result, EditableMesh). EditableMesh also caps at **60,000 vertices**. One material/texture set per MeshPart. One UV set, UVs in 0–1.
4. **Textures:** uploads up to 8K are accepted and transcoded; the renderer now supports **up to 4096×4096** (4K, streamed by mip). That does not mean you should use 4K. Size by world size: ~256 px for 5-stud props, 512 for 10-stud, 1024 for 20-stud. Avatar/PBR guidance still says 1024 max for most items. Rigid accessories sold on Marketplace: ≤ 2048.
5. **PBR = `SurfaceAppearance`** with `ColorMap`, `NormalMap` (OpenGL / Y+ tangent space), `RoughnessMap`, `MetalnessMap`, optional emissive mask; `AlphaMode` = Overlay (default) / Transparency / TintMask / Opaque(beta). Its maps **cannot be changed by normal scripts at runtime** (PluginSecurity) — swap whole instances, or build from `EditableImage` via `AssetService:CreateSurfaceAppearanceAsync`.
6. **Pick one art style and stay in it.** For an AI agent the most reliable good look is **low-poly / flat-shaded + a small palette** (parts in Studio, or meshes using a palette texture). Do not mix realistic PBR props with blocky parts.
7. **Collision:** use `Box` for small/decorative stuff, `Hull` for convex-ish props, `Default` for walk-on concave meshes, `PreciseConvexDecomposition` only when gameplay truly needs it. Set `CanCollide=false` / `CanQuery=false` / `CanTouch=false` on pure decoration.
8. **Reuse meshes.** Many copies of the same MeshId cost far less than many unique meshes. Budget unique meshes and unique textures, especially for mobile.
9. **Unions (CSG) are fine for a handful of hero pieces**; prefer plain parts or imported meshes for anything repeated hundreds of times. Never leave thousands of tiny unions in a map.
10. **Never insert a free model without auditing it.** Run the backdoor scanner in this chapter on every third-party asset. Delete every script you did not write unless you can read and justify it. Prefer original assets.
11. **Characters:** R15 is the default; custom players go in `StarterPlayer ▸ StarterCharacter` (a Model with `Humanoid` + `HumanoidRootPart`). Change avatar appearance with `HumanoidDescription` + `Humanoid:ApplyDescriptionAsync()`. NPCs: `Players:CreateHumanoidModelFromDescriptionAsync()`.
12. **Generative tools (Assistant / Cube 3D / Texture Generator / Material Generator)** are good for one-off props and quick material variants; they are bad at consistent style, precise dimensions, topology, and anything with text or logos. Always re-check tri count, scale, pivot and collision after generation.
13. **2D assets:** transparent PNG for icons/decals; UI that must stretch uses **9-slice** (`ScaleType = Slice`, `SliceCenter`). Pack small icons into sprite sheets and address them with `ImageRectOffset/ImageRectSize`.
14. **Upload by code** with the Open Cloud Assets API (`POST https://apis.roblox.com/assets/v1/assets`, header `x-api-key`), poll the returned operation, read `moderationResult`. Assets are invisible to players until moderation approves them.
15. **Everything you make should be generated by a script you can re-run** (bpy, Luau/Lune, Python+Pillow). That gives you consistency, iteration and palette discipline.

## 1. Where assets come from — decision table

| Need | Best route for an AI agent | Why |
|---|---|---|
| Blocky / stylized environment (houses, trees, fences, rocks) | **Parts built by Luau** (in Studio via MCP/command bar, or offline with Lune → `.rbxm`) | No external tools, perfect palette control, cheap to render, easy to vary procedurally |
| Organic props with silhouette (mushrooms, crystals, low-poly trees, crates with bevels) | **Blender headless (bpy)** → GLB → Importer / Open Cloud | Real meshes, low tri counts, one draw call per prop |
| Hero asset with surface detail (sword, chest, statue) | bpy mesh + baked normal/AO + `SurfaceAppearance`, or Texture Generator on your mesh | Detail without geometry |
| Many variations of a parametric thing (staircase, fence run, table+chairs) | `ProceduralModel` generator module, or a Luau builder function | Changes with Size/attributes, no re-import |
| Runtime-generated geometry (terrain chunks, player-drawn shapes, deformation) | `EditableMesh` / `EditableImage` | Only option for per-frame or per-player geometry |
| Quick filler props during prototyping | Assistant `/generate_mesh` or `GenerationService` | Fast, but inconsistent style — replace before ship if it clashes |
| Tiling surfaces (floor, wall, ground) | Built-in Materials + `MaterialVariant`, or Material Generator | Tiling textures stay crisp at any scale |
| UI icons, logos, thumbnails | Generated PNGs (Pillow/SVG → PNG), uploaded via Open Cloud | Original, consistent, scriptable |

## 2. Blender → Roblox pipeline in depth

### 2.1 Scene setup

| Setting | Value | Reason |
|---|---|---|
| Scene ▸ Units ▸ Unit System | **None** | 1 BU = 1 stud with glTF / FBX Unit Scale |
| Rotation | Degrees | readability |
| Up axis | Blender Z-up; exporters convert to Y-up | Roblox is Y-up, front = −Z |
| Scale reference | Default R15 avatar ≈ **5 studs tall** (Rthro ≈ 5.5+); a door ≈ 4×7 studs; a stair step 1 stud; a room 12–16 studs tall | Roblox scale is chunkier than real-world (1 stud ≈ 0.28 m by avatar ratio, but games build bigger) |
| Clip end | 1000+ | big scenes |

Keep a 5-stud-tall reference block in your template file (delete before export or exclude via "selected only").

### 2.2 Modeling rules (from the official mesh specs)

- **Triangle budget:** individual meshes can't exceed **20,000 triangles**. Quads count as 2 tris. Avatar parts have far smaller budgets (see §12).
- **Watertight, has volume, no zero-thickness planes** for anything that needs collision or will be sold. (For environment-only cards like grass, a single plane with `DoubleSided` works, but CollisionFidelity on a plane is meaningless.)
- **Avoid N-gons**; quads or tris.
- **No more than 4 bone influences per vertex**; root bone at 0,0,0 with no weights.
- **One material per mesh.** If your Blender object has 3 materials, the importer splits it into 3 MeshParts or you get only one texture. Plan atlases.
- **Single UV set**, coordinates in 0–1. Overlapping UVs are allowed (useful for mirrored/symmetric parts and trim sheets).
- **Normals** must face outward. Enable *Face Orientation* overlay; blue = good, red = flipped (Mesh ▸ Normals ▸ Recalculate Outside). The importer has *Invert Negative Faces* but don't rely on it.
- **Flat vs smooth shading** is exported as split normals. For low-poly style use *Shade Flat* (or Auto Smooth/“Smooth by Angle” at ~30° for bevelled hard-surface).

### 2.3 Transforms, origin, pivot, naming

| Item | Do this | Consequence if not |
|---|---|---|
| Rotation/scale | **Apply** (Ctrl+A ▸ All Transforms) | MeshPart imports rotated or stretched; skinned meshes deform wrong |
| Location | Put the object at world origin *or* enable *Insert Using Scene Position* | Model lands far from camera |
| Origin (object pivot) | Place it where the object should rotate/sit: bottom-center for props, hinge for doors, grip for tools | Importer keeps imported pivot (*Use Imported Pivot* = on by default); bad pivot = painful placement scripts |
| Model pivot | Importer *Set Pivot to Scene Origin* is **on** by default | The Model's pivot = Blender world origin. Model at origin ⇒ pivot at origin |
| Names | `Crate`, `Crate_Lid`, `Door_Hinge_Att` | Become MeshPart names. Suffixes are special: `_Att` → `Attachment`, `_OuterCage` → `WrapTarget`, `_InnerCage` + `_OuterCage` → `WrapLayer` |
| Hierarchy | Parent objects to form groups; FBX keeps parenting as Models | flat dump of parts |

### 2.4 Export formats

| Format | Use when | Notes |
|---|---|---|
| **glTF 2.0 (.glb)** | Default for static props and the bot's pipeline | No scale fiddling (docs note FBX-only scale issues). Textures embed in GLB. Hierarchy differs: each glTF mesh becomes a `Model` containing one `MeshPart` per primitive; if node & mesh share a name, one gets `_Node` suffix |
| **FBX** | Rigged/skinned meshes, animation, cages, avatar items | Path Mode = **Copy** + **Embed Textures**; Apply Scalings = **FBX Unit Scale**; disable **Add Leaf Bones**; disable **Bake Animation** unless exporting an animation (only one animation track per file) |
| **OBJ** | Simplest geometry only | No rigs, no PBR; textures via MTL are flaky — assign in Studio |

Blender FBX alternatives if scale is still wrong: Transform ▸ Scale = 0.01, or Scene Unit Scale = 0.01 (docs warn the latter causes camera/modifier issues). Many old tutorials use outdated scale advice — test with a 1×1×1 cube that must import as 1×1×1 studs.

Axis: the official Blender page says Forward = **Z Forward**, Up = **Y Up** for export, and in the Importer *World Forward = Front*, *World Up = Top*. Always sanity-check: a model whose "front" faces Blender −Y should face Roblox −Z (the `LookVector`) after import; if it is backwards, rotate 180° in Blender and re-apply, rather than fixing in Studio.

### 2.5 The Studio 3D Importer (File ▸ Import)

Accepts `.fbx`, `.gltf/.glb`, `.obj` (plus images, audio, video). Shows a preview, hierarchy, warnings/errors, and per-file/per-object settings:

| Group | Setting | Default | Recommendation |
|---|---|---|---|
| File General | Import Only As Model | — | On for multi-object props |
| | Upload to Roblox | on | On (gets asset IDs) |
| | Import as Package | off | On for reusable kits (see §15) |
| | Creator | you | Set to the **group** that owns the game, or the game can't load private assets |
| | Insert Using Scene Position | off | On only if you built the layout in Blender |
| | Set Pivot to Scene Origin | on | Keep |
| | Anchored | off | **On** for environment props |
| | Uses Cage | auto | Auto-on when cages detected |
| Rig General | Rig Type / Rig Scale / Validate UGC Body / Keep Zero Influence Bones | — | Only for rigs/avatars |
| File Transform | World Forward / World Up | Front / Top | Keep for Blender |
| File Geometry | Scale Unit | Studs | Keep (Blender units = studs) |
| | Merge Meshes | off | On to collapse a multi-part prop into **one** MeshPart (fewer instances) — only if they share a texture |
| | Invert Negative Faces | off | Last-resort fix |
| Object General | Use Imported Pivot | on | Keep |
| Object Geometry | Make Double Sided / Ignore Vertex Colors | off | Double-sided only for cards/foliage |

**Bulk import:** select multiple files in the Importer to get the **import queue** (apply presets, "Apply settings to all", import all). The **Asset Manager** also bulk-imports meshes together with images/audio, but **not** rigged/skinned/animated meshes, accessories, or heads with facial animation. Save your settings as an Importer **preset** ("Save as new", "Set as default").

**Re-import:** keep the source `.blend` and export path stable. Studio supports re-importing a changed file onto existing MeshParts (see `art/modeling/reimport.md`) so instances keep their properties.

### 2.6 Roblox Blender Plugin

The official "Roblox Blender Plugin" lets you log in and upload/re-upload meshes from Blender directly. Useful for a human artist; the bot should prefer the Open Cloud API (§17) because it is scriptable without a GUI.

### 2.7 Export checklist

- [ ] Units None, object scale 1/1/1, rotation 0/0/0 (applied)
- [ ] Origin at intended pivot; object near world origin
- [ ] Tri count < 20k (target far lower: props 50–1,500, hero 2–5k)
- [ ] One material per object; textures packed/embedded; image names unique
- [ ] Normals outward, no loose verts, merged by distance
- [ ] UVs in 0–1, single UV map
- [ ] Meaningful object names; `_Att` empties for attachment points
- [ ] glTF (static) or FBX with the settings above (rigged)
- [ ] Imported 1×1×1 test cube = 1×1×1 studs

## 3. UVs, texel density, trim sheets, tiling

### 3.1 UV unwrapping basics

- **Mark seams** on hard edges and hidden places (bottom, back, inside corners). *Smart UV Project* (angle ~66°, island margin 0.02) is acceptable for bot-generated hard-surface props. *Cube Projection* works for boxy objects.
- **Pack islands** with margin ≥ 4 px at final resolution (mip bleeding). Roblox streams lower mips first, so margins matter more than on desktop engines.
- Flat-color low-poly assets don't need a real unwrap: collapse each face's UVs to the centre of a palette cell (§5).

### 3.2 Texel density

Pick a target and keep it consistent across all props so nothing looks blurrier than its neighbour. The docs' guideline (256 px per 2×2×2-stud volume) equals ~128 px/stud. Roblox's own reference points:

| Surface | Texel density |
|---|---|
| Built-in part materials | 1024 px over 8 studs = **128 px/stud** |
| Terrain materials | 512 px over 8 studs = **64 px/stud** |
| Suggested props | 256² for ~5-stud, 512² for ~10-stud, 1024² for ~20-stud objects |

For a stylized game, 32–64 px/stud is plenty; for hand-painted, 64–128.

### 3.3 Trim sheets and tiling textures

- **Tiling texture**: seamless in both axes; used by `Texture` objects (`StudsPerTileU/V`, `OffsetStudsU/V`) on part faces, by `MaterialVariant` (applies to parts/meshes/terrain with `StudsPerTile`), or by meshes whose UVs extend beyond the island — note mesh UVs must be in 0–1 per spec, so on meshes tiling is done by `MaterialVariant` instead of UVs > 1.
- **Trim sheet**: one texture with horizontal strips (planks, metal trims, bricks, window frames). Many meshes map UV strips to it → dozens of props share **one** texture (huge memory win). Works best with overlapping UVs and a consistent texel density.
- **Atlas**: pack the textures of a kit (fence, lamp, bench) into one 1024² image; one texture, many meshes.

### 3.4 MaterialVariant (custom materials)

`MaterialService` holds `MaterialVariant` instances (ColorMap/NormalMap/RoughnessMap/MetalnessMap + `BaseMaterial` + `StudsPerTile` + physics). Set `BasePart.MaterialVariant` by name, or override a base material globally. Best way to give **parts** a custom look without meshes; the Material Generator creates these from text prompts.

## 4. Baking and PBR maps

### 4.1 SurfaceAppearance properties (verified)

| Property | Type | Notes |
|---|---|---|
| `ColorMap` / `ColorMapContent` | ContentId / Content | Albedo + alpha. `…Content` can reference an `EditableImage` |
| `NormalMap` / `NormalMapContent` | | **OpenGL format, tangent space** (green up / Y+). DirectX normals look inverted — flip G |
| `RoughnessMap` / `RoughnessMapContent` | | Single channel (red used) |
| `MetalnessMap` / `MetalnessMapContent` | | Single channel; mostly 0 or 1 |
| `EmissiveMaskContent`, `EmissiveStrength`, `EmissiveTint` | | Glowing areas |
| `AlphaMode` | `Enum.AlphaMode` | `Overlay` (default; transparent areas show `MeshPart.Color`), `Transparency` (cut-out / see-through), `TintMask` (alpha = where `SurfaceAppearance.Color` tints), `Opaque` (beta) |
| `Color` | Color3 | Tint used by TintMask |
| `ResampleMode` | | Default vs Pixelated (pixel-art textures) |

Write security for the map properties is **PluginSecurity**: game scripts can't set them. Workarounds: clone prepared `SurfaceAppearance` instances from `ReplicatedStorage`, or build one at runtime from EditableImages with `AssetService:CreateSurfaceAppearanceAsync({ColorMap = Content.fromObject(img), ...})`.

For `AlphaMode.Transparency`: leave `MeshPart.Transparency = 0` for hard cut-outs (leaves, fences, lace — gets correct depth sorting); set **≥ 0.02** for soft gradients (dirty glass, feathers).

Mesh `TextureID` is ignored when a `SurfaceAppearance` is present. `Decal` now also supports PBR maps (`ColorMapContent`, `NormalMapContent`, etc.).

### 4.2 Baking workflow (Blender Cycles)

1. Model **high-poly** (bevels, sculpt detail) and **low-poly** (game mesh) overlapping in space.
2. UV-unwrap the low-poly; create an image texture node (e.g. 1024²) in its material and select it.
3. Render engine **Cycles**, Bake panel: *Selected to Active* with cage extrusion ~0.02–0.1.
4. Bake **Normal** (Space: Tangent; G = +Y, which is OpenGL — matches Roblox), **Ambient Occlusion**, optionally **Diffuse (Color only)**.
5. Multiply AO into the albedo *lightly* for stylized looks (Roblox has no separate AO slot).
6. Save PNGs; name with affixes (`Crate_Color.png`, `Crate_Normal.png`, `Crate_Roughness.png`, `Crate_Metalness.png`) so the importer and humans can match them.

Headless baking with bpy is possible (`bpy.ops.object.bake(type='NORMAL', use_selected_to_active=True, cage_extrusion=0.05)` with Cycles, then `image.save()`), but CPU baking is slow; keep resolutions small (512²).

### 4.3 Hand-painted vs PBR vs flat

| Style | Maps | Look | Cost | Bot-friendliness |
|---|---|---|---|---|
| **Flat low-poly + palette** | 1 tiny palette texture (or none — part colors / vertex colors) | Clean, readable, timeless | Lowest | **Best** |
| Hand-painted stylized | ColorMap only (lighting painted in, soft), no normal | Warcraft/Fortnite-ish | Low | Medium (procedural gradients + AO bake help) |
| Stylized PBR | Color + Normal + Roughness, low metal | Modern Roblox "front page" | Medium | Medium (Texture Generator "Quality") |
| Realistic PBR | All maps, 1–2K | Showcase realism | High; clashes with avatars | Low |

Rule: **diffuse maps with baked lighting look wrong under PBR lighting**. If you hand-paint, keep the painted shading subtle and let the engine light it.

## 5. Low-poly flat-shaded style (recommended default for the bot)

Why it works for an agent: geometry is simple enough to describe in code, there is no texture authoring, and colour comes from a fixed palette, so every asset matches.

Three ways to colour flat low-poly meshes:

| Method | How | Pros / cons |
|---|---|---|
| **Palette texture** | 1 small image (e.g. 128² holding an 8×8 grid of colours); each face's UVs collapsed to a cell centre | All props share ONE texture; recolour the whole game by editing one PNG |
| **Vertex colours** | Paint per-face colours in Blender (Color Attribute), export FBX/glTF | No texture at all; importer supports vertex colours (*Ignore Vertex Colors* off). Some pipelines drop them — test |
| **Split by colour** | Separate objects per colour, colour via `MeshPart.Color` | Easy recolouring in Studio; more instances |

### Palette discipline

- Choose **5–8 hues × 3 values** (shadow / base / highlight). Example "meadow" palette: grass `#6DBE45 / #4E9A35 / #9BD66A`, bark `#7A4E2D / #5A3820 / #9C6B43`, stone `#8C8F99 / #6B6E77 / #B5B8C2`, roof `#C2523C / #8F3A2A / #E07A5F`, wall `#F2E6D0 / #D9C8A9 / #FFF6E5`, water `#3FA7D6`, accent `#F4C542`.
- Keep saturation moderate (Roblox's tone mapping and bloom push saturated colours to neon).
- Store the palette in **one ModuleScript** (`ReplicatedStorage.Art.Palette`) and in the Blender script as the same hex list. Never type ad-hoc `Color3.fromRGB` values in builders.
- Use `Enum.Material.SmoothPlastic` (or a single matte `MaterialVariant`) for flat style; mixing `Plastic` studs/`Wood`/`Brick` grain breaks it.
- Vary **value**, not hue, for variety: jitter brightness ±6% per instance.

## 6. Level of detail and RenderFidelity

`MeshPart.RenderFidelity` (`Enum.RenderFidelity`): `Automatic` (default), `Precise`, `Performance`.

| Distance from camera (Automatic) | Fidelity |
|---|---|
| < 250 studs | Highest |
| 250–500 | Medium |
| > 500 | Lowest |

- `Precise` = always full detail (hero objects you look at closely from far away; costs more).
- `Performance` = always simplified (background clutter).
- Roblox auto-generates LODs; you can't import your own LOD chain. For large distant scenery, make a cheap low-poly version and swap via `Model.LevelOfDetail` (StreamingMesh imposters for streamed models) or manual distance swaps.
- `Model.LevelOfDetail = StreamingMesh` + `ModelStreamingMode` give streaming imposters when Workspace streaming is on (covered in the performance chapter); design big landmarks as a single Model so their imposter is meaningful.

## 7. CollisionFidelity choices

| Value | Shape | Use for | Cost |
|---|---|---|---|
| `Box` | bounding box | small props, decorations, debris, anything the player won't walk inside | lowest |
| `Hull` | one convex hull | rocks, barrels, crates, vehicles' bodies | low |
| `Default` | approximate convex decomposition | walk-on concave meshes (arches, stairs, ramps) | medium |
| `PreciseConvexDecomposition` | most precise decomposition | doorways/tunnels the player must pass through exactly | highest; slow to compute |
| `Tunable` | exposes `CollisionPrecision` slider | dial between coarse and fine without changing mode | varies |

Rules:
- Decoration with no gameplay role: `CanCollide=false`, `CanTouch=false`, `CanQuery=false` (if not needed for raycasts) — collision geometry is then irrelevant.
- For complex walk-on meshes, often better: `CanCollide=false` on the mesh + **invisible primitive Parts** as hand-placed colliders.
- `CollisionFidelity` can't be set by scripts on an existing MeshPart; pass it in `AssetService:CreateMeshPartAsync(content, {CollisionFidelity = ..., RenderFidelity = ...})`.
- Visualize with Studio's *Visualization Options ▸ Collision fidelity*.

## 8. Studio built-in modeling: parts, CSG, unions

### 8.1 Parts

- Primitives: `Part` with `Shape` = Block / Ball / Cylinder (axis along **X**) / Wedge / CornerWedge; plus `WedgePart`, `CornerWedgePart`, `TrussPart`.
- A `WedgePart`'s sloped face is its **Front (−Z)** face; the tall vertical face is at **+Z**.
- Parts are extremely cheap and batch well; thousands of anchored, same-material parts are fine. They are the bot's main building block.
- Use `SmoothPlastic` for clean stylized look; `Neon` sparingly (glow); `ForceField` for magic.
- `Texture` (tiling, `StudsPerTileU/V`) and `Decal` (stretched image, one face) add detail to parts.

### 8.2 Solid modeling (CSG)

- Studio: Union / Intersect / Negate / Separate. In-game: `GeometryService:UnionAsync`, `SubtractAsync`, `IntersectAsync`, `FragmentAsync`, `SweepPartAsync`, `SplitApartAsync` (results are unparented — parent them and destroy originals).
- Results > 20,000 tris get simplified to 20k or error.
- Each union is a **unique mesh** (memory + download) with physics decomposition — the opposite of the "reuse" principle. Copies of the same union share data, but every *edited* union is new.
- `PartOperation.UsePartColor` = single colour instead of per-face colours. `SmoothingAngle` softens normals.
- Set union `CollisionFidelity` to `Box`/`Hull` where possible; default decomposition on complex unions is expensive.
- Use CSG for: a few arches, window cut-outs on a hero building, destructible walls (FragmentAsync). Avoid: hundreds of decorative unions, unions inside frequently cloned models — export to Blender and make a real mesh instead.

### 8.3 Procedural models (Studio feature)

A `ProceduralModel` runs a **generator ModuleScript** (`Attributes` defaults + `OnGenerate(params, targetContainer)`) whenever its attributes or `Size` change, writing into a `GeneratedFolder`. Use it for parametric kit pieces (stairs, fences, shelves) that designers resize. Content generated around the origin; never touch the DataModel directly from `OnGenerate`. Creator Store procedural models are inserted with `Sandboxed = true` on the generator.

## 9. Building from parts procedurally (Luau)

This is the most dependable way for the bot to produce good-looking environment art. Principles:

1. **Palette module** — single source of colour.
2. **`make(props)` helper** — every part anchored, SmoothPlastic, correct collision flags.
3. **Seeded randomness** (`Random.new(seed)`) — reproducible variety.
4. **Proportions over detail** — chunky silhouettes, slight random tilt (2–6°), overlapping shapes, value variation.
5. **Group into a Model with a sensible pivot** (bottom-center) so placement is `model:PivotTo(cf)`.

```lua
--!strict
-- ReplicatedStorage/Art/StylizedBuilders.lua
-- Builds stylized low-poly trees and houses out of plain Parts.
-- Works in a Script, the Studio command bar, a plugin, or (with tiny tweaks) Lune.

local Builders = {}

export type Palette = { [string]: Color3 }

local PALETTE: Palette = {
	Leaf = Color3.fromHex("6DBE45"),
	LeafDark = Color3.fromHex("4E9A35"),
	LeafLight = Color3.fromHex("9BD66A"),
	Bark = Color3.fromHex("7A4E2D"),
	BarkDark = Color3.fromHex("5A3820"),
	Wall = Color3.fromHex("F2E6D0"),
	WallTrim = Color3.fromHex("D9C8A9"),
	Roof = Color3.fromHex("C2523C"),
	RoofDark = Color3.fromHex("8F3A2A"),
	Wood = Color3.fromHex("9C6B43"),
	Glass = Color3.fromHex("9ED8F0"),
	Stone = Color3.fromHex("8C8F99"),
}
Builders.Palette = PALETTE

-- Slight value jitter keeps repeated parts from looking copy-pasted.
local function jitter(c: Color3, rng: Random, amount: number): Color3
	local h, s, v = c:ToHSV()
	return Color3.fromHSV(h, s, math.clamp(v * (1 + rng:NextNumber(-amount, amount)), 0, 1))
end

type PartProps = {
	Name: string?,
	Size: Vector3,
	CFrame: CFrame,
	Color: Color3,
	Shape: Enum.PartType?,
	Class: string?, -- "Part" | "WedgePart"
	Material: Enum.Material?,
	Transparency: number?,
	Collide: boolean?,
	Parent: Instance,
}

local function make(p: PartProps): BasePart
	local part = Instance.new(p.Class or "Part") :: BasePart
	if p.Shape and part:IsA("Part") then
		part.Shape = p.Shape
	end
	part.Name = p.Name or "Part"
	part.Size = p.Size
	part.CFrame = p.CFrame
	part.Color = p.Color
	part.Material = p.Material or Enum.Material.SmoothPlastic
	part.Transparency = p.Transparency or 0
	part.Anchored = true
	part.TopSurface = Enum.SurfaceType.Smooth
	part.BottomSurface = Enum.SurfaceType.Smooth
	local collide = p.Collide ~= false
	part.CanCollide = collide
	part.CanTouch = false
	part.CanQuery = collide
	part.Parent = p.Parent
	return part
end

--[[ Stylized tree: tapered, slightly leaning trunk + 3-6 overlapping leaf blobs.
     style = "round" (balls) or "lowpoly" (rotated blocks, faceted look) ]]
function Builders.Tree(origin: CFrame, seed: number, style: string?): Model
	local rng = Random.new(seed)
	local model = Instance.new("Model")
	model.Name = "Tree"

	local height = rng:NextNumber(7, 11)
	local radius = rng:NextNumber(0.7, 1.0)
	local lean = CFrame.Angles(math.rad(rng:NextNumber(-5, 5)), 0, math.rad(rng:NextNumber(-5, 5)))

	-- Trunk built from 3 stacked cylinders that shrink upward (taper).
	local segments = 3
	local segH = height / segments
	local cursor = origin * lean
	for i = 1, segments do
		local r = radius * (1 - (i - 1) * 0.18)
		make({
			Name = "Trunk",
			Class = "Part",
			Shape = Enum.PartType.Cylinder,
			-- Cylinder axis is X, so rotate 90 degrees about Z to stand it up.
			Size = Vector3.new(segH + 0.2, r * 2, r * 2),
			CFrame = cursor * CFrame.new(0, segH / 2, 0) * CFrame.Angles(0, 0, math.rad(90)),
			Color = jitter(i == 1 and PALETTE.BarkDark or PALETTE.Bark, rng, 0.05),
			Parent = model,
		})
		cursor = cursor * CFrame.new(0, segH, 0) * CFrame.Angles(math.rad(rng:NextNumber(-4, 4)), 0, math.rad(rng:NextNumber(-4, 4)))
	end

	-- Canopy: one big central blob + satellites, all non-colliding decoration.
	local top = cursor
	local blobs = rng:NextInteger(3, 6)
	local leafColors = { PALETTE.Leaf, PALETTE.LeafDark, PALETTE.LeafLight }
	for i = 0, blobs do
		local size = (i == 0) and rng:NextNumber(5.5, 7) or rng:NextNumber(3, 4.5)
		local offset = (i == 0) and Vector3.new(0, 1, 0)
			or Vector3.new(rng:NextNumber(-2.4, 2.4), rng:NextNumber(-0.8, 2.2), rng:NextNumber(-2.4, 2.4))
		local cf = top * CFrame.new(offset)
		if style == "lowpoly" then
			cf = cf * CFrame.Angles(rng:NextNumber(0, math.pi), rng:NextNumber(0, math.pi), rng:NextNumber(0, math.pi))
			make({
				Name = "Leaves", Size = Vector3.new(size, size * 0.85, size), CFrame = cf,
				Color = jitter(leafColors[(i % 3) + 1], rng, 0.06), Collide = false, Parent = model,
			})
		else
			make({
				Name = "Leaves", Shape = Enum.PartType.Ball, Size = Vector3.one * size, CFrame = cf,
				Color = jitter(leafColors[(i % 3) + 1], rng, 0.06), Collide = false, Parent = model,
			})
		end
	end

	model.WorldPivot = origin -- pivot at the base of the trunk
	return model
end

--[[ Stylized house: stone plinth, walls with trim, door, windows,
     two sloped roof slabs and wedge gables. Footprint W x D, wall height H. ]]
function Builders.House(origin: CFrame, seed: number, W: number?, D: number?, H: number?): Model
	local rng = Random.new(seed)
	local w, d, h = W or 16, D or 12, H or 9
	local t = 1 -- wall thickness
	local model = Instance.new("Model")
	model.Name = "House"

	-- Plinth
	make({ Name = "Plinth", Size = Vector3.new(w + 1, 1, d + 1), CFrame = origin * CFrame.new(0, 0.5, 0),
		Color = jitter(PALETTE.Stone, rng, 0.04), Parent = model })
	local base = origin * CFrame.new(0, 1, 0)

	-- Four walls
	local wallColor = jitter(PALETTE.Wall, rng, 0.03)
	local walls = {
		{ Vector3.new(w, h, t), CFrame.new(0, h / 2, -d / 2 + t / 2) }, -- front (-Z)
		{ Vector3.new(w, h, t), CFrame.new(0, h / 2, d / 2 - t / 2) }, -- back
		{ Vector3.new(t, h, d - 2 * t), CFrame.new(-w / 2 + t / 2, h / 2, 0) },
		{ Vector3.new(t, h, d - 2 * t), CFrame.new(w / 2 - t / 2, h / 2, 0) },
	}
	for _, wl in walls do
		make({ Name = "Wall", Size = wl[1], CFrame = base * wl[2], Color = wallColor, Parent = model })
	end

	-- Corner posts and top trim beam (darker value = readable silhouette)
	for _, sx in { -1, 1 } do
		for _, sz in { -1, 1 } do
			make({ Name = "Post", Size = Vector3.new(1.2, h, 1.2),
				CFrame = base * CFrame.new(sx * (w / 2), h / 2, sz * (d / 2)),
				Color = PALETTE.Wood, Parent = model })
		end
	end
	make({ Name = "Trim", Size = Vector3.new(w + 1.2, 0.8, d + 1.2), CFrame = base * CFrame.new(0, h, 0),
		Color = PALETTE.Wood, Parent = model })

	-- Door and windows sit 0.1 proud of the front face (avoids z-fighting)
	local front = -d / 2 - 0.1
	make({ Name = "Door", Size = Vector3.new(3.5, 6, 0.4), CFrame = base * CFrame.new(0, 3, front),
		Color = PALETTE.Wood, Collide = false, Parent = model })
	for _, sx in { -1, 1 } do
		local cf = base * CFrame.new(sx * w * 0.3, h * 0.55, front)
		make({ Name = "WindowFrame", Size = Vector3.new(3.2, 3.2, 0.3), CFrame = cf, Color = PALETTE.WallTrim, Collide = false, Parent = model })
		make({ Name = "WindowGlass", Size = Vector3.new(2.4, 2.4, 0.35), CFrame = cf, Color = PALETTE.Glass,
			Material = Enum.Material.Glass, Transparency = 0.3, Collide = false, Parent = model })
	end

	-- Roof: pitch angle from gable height
	local gableH = w * 0.35
	local pitch = math.atan(gableH / (w / 2))
	local slopeLen = math.sqrt((w / 2) ^ 2 + gableH ^ 2) + 1.5 -- + eave overhang
	local roofTop = base * CFrame.new(0, h + 0.4, 0)
	local roofColor = jitter(PALETTE.Roof, rng, 0.04)
	for _, side in { -1, 1 } do
		-- Rotate about Z: left slab rises toward the ridge (+pitch), right slab mirrored.
		local cf = roofTop * CFrame.new(side * w / 4, gableH / 2, 0) * CFrame.Angles(0, 0, -side * pitch)
			* CFrame.new(0, 0.35, 0) -- lift half the slab thickness so it sits on the gable
		make({ Name = "Roof", Size = Vector3.new(slopeLen, 0.7, d + 2.5), CFrame = cf, Color = roofColor, Parent = model })
	end
	make({ Name = "Ridge", Size = Vector3.new(1, 1, d + 2.6), CFrame = roofTop * CFrame.new(0, gableH + 0.5, 0),
		Color = PALETTE.RoofDark, Parent = model })

	-- Gables: two WedgeParts per end. Wedge local +Z (tall side) points at the ridge line.
	for _, sz in { -1, 1 } do
		local zPos = sz * (d / 2 - t / 2)
		for _, sx in { -1, 1 } do
			-- sx=-1 (left half): local Z -> world +X  => rotate +90 deg about Y
			local cf = roofTop * CFrame.new(sx * w / 4, gableH / 2, zPos) * CFrame.Angles(0, -sx * math.pi / 2, 0)
			make({ Name = "Gable", Class = "WedgePart", Size = Vector3.new(t, gableH, w / 2), CFrame = cf,
				Color = wallColor, Parent = model })
		end
	end

	-- Chimney (random side) for silhouette interest
	local cx = (rng:NextNumber() < 0.5 and -1 or 1) * w * 0.25
	make({ Name = "Chimney", Size = Vector3.new(1.6, gableH + 2, 1.6), CFrame = roofTop * CFrame.new(cx, gableH / 2 + 1, d * 0.2),
		Color = PALETTE.Stone, Parent = model })

	model.WorldPivot = origin
	return model
end

return Builders
```

## 10. Generating meshes in Blender headlessly (bpy)

Run with: `blender -b --factory-startup -P make_lowpoly_tree.py -- --out ./out/PineTree --seed 7`

The script below builds a flat-shaded low-poly pine tree on rocks, colours it with a shared **palette texture** (UV-collapsed faces), applies transforms, sets the origin at the base, checks the triangle budget, and exports GLB (preferred) plus FBX (Roblox settings).

```python
# make_lowpoly_tree.py — Blender 4.x, run headless:
#   blender -b --factory-startup -P make_lowpoly_tree.py -- --out out/PineTree --seed 7
import bpy, bmesh, random, sys, os, argparse, math

argv = sys.argv[sys.argv.index("--") + 1:] if "--" in sys.argv else []
ap = argparse.ArgumentParser()
ap.add_argument("--out", default="out/PineTree")
ap.add_argument("--seed", type=int, default=1)
ap.add_argument("--max_tris", type=int, default=1500)
args = ap.parse_args(argv)
random.seed(args.seed)
os.makedirs(os.path.dirname(os.path.abspath(args.out)), exist_ok=True)

# ---------- scene ----------
bpy.ops.wm.read_factory_settings(use_empty=True)
scene = bpy.context.scene
scene.unit_settings.system = 'NONE'          # 1 BU = 1 stud

# ---------- palette (same hex list as the Luau Palette module) ----------
PALETTE = ["6DBE45", "4E9A35", "9BD66A", "7A4E2D", "5A3820", "8C8F99",
           "6B6E77", "B5B8C2", "C2523C", "F2E6D0", "3FA7D6", "F4C542"]
GRID, CELL = 8, 16                            # 8x8 cells, 16 px each -> 128x128 image
def hex_rgb(h): return tuple(int(h[i:i+2], 16) / 255 for i in (0, 2, 4))

def make_palette_image(path):
    size = GRID * CELL
    img = bpy.data.images.new("Palette", size, size, alpha=False)
    px = [0.0] * (size * size * 4)
    for idx, hx in enumerate(PALETTE):
        cx, cy = idx % GRID, idx // GRID
        r, g, b = hex_rgb(hx)
        for y in range(cy * CELL, (cy + 1) * CELL):
            for x in range(cx * CELL, (cx + 1) * CELL):
                i = (y * size + x) * 4
                px[i:i+4] = [r, g, b, 1.0]
    img.pixels = px
    img.filepath_raw = path
    img.file_format = 'PNG'
    img.save()
    return img

def cell_uv(idx):
    cx, cy = idx % GRID, idx // GRID
    return ((cx + 0.5) / GRID, (cy + 0.5) / GRID)

palette_img = make_palette_image(os.path.abspath(args.out + "_Palette.png"))

mat = bpy.data.materials.new("PaletteMat")
mat.use_nodes = True
nt = mat.node_tree
bsdf = nt.nodes["Principled BSDF"]
bsdf.inputs["Roughness"].default_value = 1.0
tex = nt.nodes.new("ShaderNodeTexImage")
tex.image = palette_img
tex.interpolation = 'Closest'
nt.links.new(tex.outputs["Color"], bsdf.inputs["Base Color"])

# ---------- helpers ----------
def paint(obj, color_index_fn):
    """Collapse each face's UVs onto one palette cell; flat shade."""
    me = obj.data
    uv = me.uv_layers.new(name="UVMap")
    for poly in me.polygons:
        poly.use_smooth = False
        u, v = cell_uv(color_index_fn(poly))
        for li in poly.loop_indices:
            uv.data[li].uv = (u, v)
    me.materials.append(mat)

def jitter_verts(obj, amount):
    bm = bmesh.new(); bm.from_mesh(obj.data)
    for v in bm.verts:
        v.co.x += random.uniform(-amount, amount)
        v.co.y += random.uniform(-amount, amount)
        v.co.z += random.uniform(-amount * 0.5, amount * 0.5)
    bm.to_mesh(obj.data); bm.free()

parts = []

# Trunk: 6-sided tapered cylinder, base at z=0
bpy.ops.mesh.primitive_cone_add(vertices=6, radius1=0.55, radius2=0.35, depth=3.0, location=(0, 0, 1.5))
trunk = bpy.context.active_object
paint(trunk, lambda p: 3 if p.normal.z < 0.9 else 4)   # bark; caps darker
parts.append(trunk)

# Foliage: 3 stacked cones, each a bit smaller and rotated
z, r = 2.2, 2.6
for tier in range(3):
    h = 2.6 - tier * 0.35
    bpy.ops.mesh.primitive_cone_add(vertices=7, radius1=r, radius2=0.0, depth=h,
                                    location=(0, 0, z + h / 2),
                                    rotation=(0, 0, random.uniform(0, math.pi)))
    cone = bpy.context.active_object
    jitter_verts(cone, 0.18)
    # light on upward faces, dark underneath -> fake lighting in the palette
    paint(cone, lambda p: 2 if p.normal.z > 0.55 else (0 if p.normal.z > 0 else 1))
    parts.append(cone)
    z += h * 0.55
    r *= 0.72

# Rocks around the base
for i in range(3):
    a = random.uniform(0, 2 * math.pi)
    bpy.ops.mesh.primitive_ico_sphere_add(subdivisions=1, radius=random.uniform(0.35, 0.6),
                                          location=(math.cos(a) * 1.1, math.sin(a) * 1.1, 0.15))
    rock = bpy.context.active_object
    rock.scale = (1.0, 0.8, 0.6)
    jitter_verts(rock, 0.06)
    paint(rock, lambda p: 7 if p.normal.z > 0.5 else 5)
    parts.append(rock)

# ---------- join, apply, origin ----------
bpy.ops.object.select_all(action='DESELECT')
for o in parts:
    o.select_set(True)
bpy.context.view_layer.objects.active = trunk
bpy.ops.object.join()
obj = bpy.context.active_object
obj.name = os.path.basename(args.out)                 # becomes the MeshPart name
obj.data.name = obj.name
bpy.ops.object.transform_apply(location=False, rotation=True, scale=True)
scene.cursor.location = (0, 0, 0)
bpy.ops.object.origin_set(type='ORIGIN_CURSOR')       # pivot at base centre
bpy.ops.object.mode_set(mode='EDIT')
bpy.ops.mesh.select_all(action='SELECT')
bpy.ops.mesh.remove_doubles(threshold=0.0001)
bpy.ops.mesh.normals_make_consistent(inside=False)
bpy.ops.object.mode_set(mode='OBJECT')

tris = sum(len(p.vertices) - 2 for p in obj.data.polygons)
dims = obj.dimensions
print(f"[asset] {obj.name}: {tris} tris, size {dims.x:.2f} x {dims.z:.2f}(h) x {dims.y:.2f} studs")
if tris > args.max_tris:
    mod = obj.modifiers.new("Decimate", 'DECIMATE')
    mod.ratio = args.max_tris / tris
    bpy.ops.object.modifier_apply(modifier=mod.name)
    print(f"[asset] decimated to {sum(len(p.vertices) - 2 for p in obj.data.polygons)} tris")
assert tris < 20000, "Roblox per-mesh limit is 20,000 triangles"

# ---------- export ----------
bpy.ops.object.select_all(action='DESELECT')
obj.select_set(True)

bpy.ops.export_scene.gltf(
    filepath=os.path.abspath(args.out + ".glb"),
    export_format='GLB', use_selection=True, export_yup=True, export_apply=True)

bpy.ops.export_scene.fbx(
    filepath=os.path.abspath(args.out + ".fbx"),
    use_selection=True,
    apply_scale_options='FBX_SCALE_UNITS',   # "Apply Scalings: FBX Unit Scale"
    axis_forward='-Z', axis_up='Y',          # Blender defaults; Roblox doc suggests "Z Forward" - verify facing
    mesh_smooth_type='FACE',                 # keep flat shading
    path_mode='COPY', embed_textures=True,
    add_leaf_bones=False, bake_anim=False)
print("[asset] exported", args.out)
```

Why the palette trick looks good: shading is "painted" by face normal (light tops, dark undersides), so even under flat ambient light the tree reads well, and every asset made this way shares one 128² texture. On import, if the texture gets blurry at distance due to mip filtering, increase `CELL` (32 px) — the image is still tiny.

### 10.1 bpy recipes worth knowing

| Goal | bpy |
|---|---|
| Bevel hard-surface edges | `obj.modifiers.new("Bevel","BEVEL"); mod.width=0.05; mod.segments=2` then apply |
| Reduce tris | `DECIMATE` modifier (`ratio`, or `decimate_type='PLANAR'` for flat surfaces) |
| Mirror symmetric models | `MIRROR` modifier, apply before export |
| Auto UV | `bpy.ops.uv.smart_project(angle_limit=math.radians(66), island_margin=0.02)` in Edit mode |
| Vertex colours instead of palette | `me.color_attributes.new("Col", 'BYTE_COLOR', 'CORNER')` and write per-loop colours |
| Batch | loop seeds/args in one Blender process; reset with `read_factory_settings` between assets |
| Check orientation | Build so the object's "front" faces Blender **−Y** |
| Render a thumbnail | add camera + sun, `scene.render.filepath=...; bpy.ops.render.render(write_still=True)` (Eevee/Workbench headless) |

Blender in CI: `apt install blender` versions lag; prefer the official tarball. `--factory-startup` avoids user add-ons. Use `-noaudio` on servers without audio.

## 11. Runtime and code-generated meshes: EditableMesh / EditableImage

### 11.1 Key facts (verified)

- Create: `AssetService:CreateEditableMesh()` (empty, resizable) or `AssetService:CreateEditableMeshAsync(content, {FixedSize = false})` (from an asset; fixed-size by default = cheaper, only positions/attributes editable).
- Display: `AssetService:CreateMeshPartAsync(Content.fromObject(editableMesh), {CollisionFidelity=…, RenderFidelity=…})`, or `existingMeshPart:ApplyMesh(newMeshPart)`. One EditableMesh can be referenced by many MeshParts.
- Collision does **not** update automatically after edits; re-run `CreateMeshPartAsync` + `ApplyMesh` at the end of a conceptual edit. Visuals update immediately.
- Limits: **60,000 vertices, 20,000 triangles**; quads count as 2.
- Faces wind **counter-clockwise** for the front; `MeshPart.DoubleSided` to show both.
- Normals/UVs/colours are per face-corner; create new attribute IDs (`AddNormal`, `AddUV`, `AddColor`) and `SetFaceNormals`/`SetFaceUVs`/`SetFaceColors` for hard edges and colour seams. Prefer **Batch** methods (`BatchAdd`, `BatchSetValues`, …) for speed.
- **Published games:** must enable *Allow Mesh / Image APIs* (Game Settings ▸ Security) — off by default.
- Loading existing assets is permission-gated (asset owned by/shared with the game owner, Studio user, or the client player).
- Client memory budget is strict; creation returns `nil` when exhausted — always nil-check. Server/Studio/plugins are unlimited.
- `EditableImage`: `AssetService:CreateEditableImage({Size = Vector2.new(w, h)})`, max **1024×1024**, pixel ops via `WritePixelsBuffer(position, size, buffer)` / `ReadPixelsBuffer`, plus `DrawRectangle`, `DrawCircle`, `DrawLine`, `DrawImage`, `DrawImageTransformed`, `DrawImageProjected`. Display via `ImageLabel.ImageContent`, `MeshPart.TextureContent`, `Decal.ColorMapContent`, or `CreateSurfaceAppearanceAsync`.

### 11.2 Example: flat-shaded low-poly terrain tile with per-face colours

```lua
-- Server Script: generate a faceted hill tile with EditableMesh (requires Mesh/Image APIs enabled).
local AssetService = game:GetService("AssetService")

local N, CELL = 16, 4               -- 16x16 cells, 4 studs each => 64x64 stud tile, 512 tris
local GRASS = { Color3.fromHex("6DBE45"), Color3.fromHex("4E9A35"), Color3.fromHex("9BD66A") }

local em = AssetService:CreateEditableMesh()
assert(em, "editable memory budget exhausted")

local function heightAt(x: number, z: number): number
	return math.noise(x * 0.08, z * 0.08, 3.1) * 10 + math.noise(x * 0.25, z * 0.25) * 1.5
end

local verts = {}
for i = 0, N do
	verts[i] = {}
	for j = 0, N do
		local x, z = (i - N / 2) * CELL, (j - N / 2) * CELL
		verts[i][j] = em:AddVertex(Vector3.new(x, heightAt(x, z), z))
	end
end

local colorIds = {}
for k, c in GRASS do colorIds[k] = em:AddColor(c, 1) end

local rng = Random.new(1)
local function flatTri(a, b, c)
	local fid = em:AddTriangle(a, b, c)
	local nid = em:AddNormal()                  -- auto-computed, unshared => faceted
	em:SetFaceNormals(fid, { nid, nid, nid })
	local col = colorIds[rng:NextInteger(1, #colorIds)]
	em:SetFaceColors(fid, { col, col, col })
end

for i = 0, N - 1 do
	for j = 0, N - 1 do
		local v00, v10, v01, v11 = verts[i][j], verts[i + 1][j], verts[i][j + 1], verts[i + 1][j + 1]
		-- counter-clockwise when viewed from above (+Y)
		flatTri(v00, v01, v10)
		flatTri(v10, v01, v11)
	end
end

local part = AssetService:CreateMeshPartAsync(Content.fromObject(em), {
	CollisionFidelity = Enum.CollisionFidelity.Default,
})
part.Anchored = true
part.Material = Enum.Material.SmoothPlastic
part.Position = Vector3.new(0, 5, 0)
part.Parent = workspace
```

If triangles render inside-out, swap two vertex arguments in `flatTri`. Use EditableMesh for genuinely dynamic content; for static generated art, generate in Studio once and **save** (via the AssetService `CreateAssetAsync` flow or by exporting and re-importing) so players don't pay generation cost and memory every session.

### 11.3 Procedural textures

- **At build time (preferred):** Python + Pillow/NumPy produce PNGs (palette strips, gradients, noise, tiling stone, UI icons), then upload via Open Cloud.
- **At runtime:** `EditableImage` with a `buffer` of RGBA bytes (row-major, top-left origin, 4 bytes per pixel).

```python
# gen_textures.py — seamless stylized tile + vertical gradient (pip install pillow numpy)
import numpy as np
from PIL import Image

def seamless_noise(size=256, octaves=4, seed=0):
    """Sum of upscaled periodic random grids -> tiles seamlessly."""
    rng = np.random.default_rng(seed)
    out = np.zeros((size, size))
    for o in range(octaves):
        n = 4 * 2 ** o                                   # grid cells per side
        grid = rng.random((n, n))
        padded = np.pad(grid, 1, mode="wrap")            # wrap edges so borders match
        cell = size / n
        big = Image.fromarray((padded * 255).astype(np.uint8)).resize(
            (int(size + 2 * cell), int(size + 2 * cell)), Image.BICUBIC)
        c = int(cell)
        arr = np.asarray(big, dtype=float)[c:c + size, c:c + size] / 255
        out += arr / 2 ** o
    return (out - out.min()) / (out.max() - out.min())

def colorize(v, dark, base, light):
    d, b, l = (np.frombuffer(bytes.fromhex(h), dtype=np.uint8).astype(float) for h in (dark, base, light))
    v = v[..., None]
    rgb = np.where(v < 0.5, d + (b - d) * (v / 0.5), b + (l - b) * ((v - 0.5) / 0.5))
    # posterize to 5 bands for a hand-painted feel
    return (np.round(rgb / 255 * 5) / 5 * 255).astype(np.uint8)

grass = colorize(seamless_noise(256, seed=3), "4E9A35", "6DBE45", "9BD66A")
Image.fromarray(grass).save("Grass_Color.png")

h = 256
grad = np.linspace(0, 1, h)[:, None, None]
top, bot = np.array([0x9B, 0xD6, 0x6A]), np.array([0x4E, 0x9A, 0x35])
Image.fromarray((bot + (top - bot) * (1 - grad)).repeat(16, axis=1).astype(np.uint8)).save("Leaf_Gradient.png")
```

Always preview a 3×3 tiling (`np.tile(img, (3, 3, 1))`) before uploading a "seamless" texture; bicubic resampling can leave a faint seam, which a 1–2 px edge blend fixes.

## 12. Characters

### 12.1 Rig types

| Rig | Parts | Use |
|---|---|---|
| **R15** (default) | 15 MeshParts: Head, UpperTorso, LowerTorso, Left/Right Upper/Lower Arm, Hands, Upper/Lower Leg, Feet; joints are `Motor6D`; `HumanoidRootPart` root | Players, NPCs that wear avatar items, layered clothing, emotes, animation packs |
| R6 | 6 parts | Retro feel, simpler animation; no layered clothing, limited avatar features |
| Custom rig | Any skinned/jointed model with `Humanoid` or custom controller | Monsters, animals, vehicles-as-characters |

Set default player rig/scales in **Game Settings ▸ Avatar** (Avatar type, body scale ranges, animation, collision). These are the "global avatar settings".

### 12.2 Avatar body budgets (Marketplace bodies, also good targets for NPCs)

| Asset | Meshes | Max tris |
|---|---|---|
| DynamicHead | Head | 4,000 |
| Torso | UpperTorso, LowerTorso | 1,750 |
| Each arm | Upper, Lower, Hand | 1,248 |
| Each leg | Upper, Lower, Foot | 1,248 |
| Rigid accessory | — | 4,000 |

Character body textures: up to 1024² for a full humanoid (PBR budget table). Rigid accessories for Marketplace: ≤ 2048²; non-albedo maps for accessories 256².

### 12.3 Custom player characters (StarterCharacter)

- Put a Model named **`StarterCharacter`** in `StarterPlayer`. It must contain a **`Humanoid`** and a **`HumanoidRootPart`** (set as `PrimaryPart`), parts joined by `Motor6D` (rigid) or a skinned mesh with `Bone`s. All parts **unanchored**; HRP usually transparent and `CanCollide` behaviour handled by the Humanoid.
- For an R15-compatible custom character, keep R15 part names and joint names so default animations and `Animate` script work. Otherwise provide your own `Animate` LocalScript (copy from a play-test character under `StarterCharacterScripts`) with your animation IDs.
- `StarterHumanoid` customizes default humanoid properties without replacing the body.
- Set `Humanoid.HipHeight` correctly for custom rigs (distance from HRP bottom to ground) or characters float/sink.
- Players' own avatars are **replaced** by StarterCharacter — consider whether your game needs that (it removes self-expression, a big part of Roblox's appeal). Middle ground: keep avatars, restrict scales/body types in Avatar settings, or apply themed outfits via `HumanoidDescription`.

### 12.4 Skinned meshes and rigging in Blender

- Armature with bones; root bone at origin, zero rotation, scale 1; ≤ 4 influences per vertex; no weights on root.
- Export FBX: Add Leaf Bones **off**, Apply Scalings FBX Unit Scale, Bake Animation off (unless including one animation).
- Importer: *Rig Type* (R15 / Custom), *Rig Scale*. Imported skinned MeshParts show `HasSkinnedMesh = true`; bones appear as `Bone` instances animatable with the Animation Editor.
- For R15 avatars, use the official Blender template rigs from the docs' project files rather than authoring a skeleton from scratch; Studio's **Avatar Setup** tool can auto-rig/skin/cage a single mesh body ("auto setup") — useful for an agent that can only produce an unrigged mesh. Check `avatar-setup/auto-setup-requirements.md` for its constraints (humanoid T/A-pose, watertight, budget).

### 12.5 Layered clothing and accessories

- **Rigid accessory**: `Accessory` with a `Handle` (MeshPart) and an `Attachment` matching a character attachment name (`HatAttachment`, `FaceFrontAttachment`, `WaistBackAttachment`, …). `Humanoid:AddAccessory(acc)` welds it.
- **Layered accessory** (clothing that wraps): mesh + `WrapLayer` with **inner and outer cages** (`_InnerCage`, `_OuterCage` naming in Blender; don't change cage vertex count/UVs). The body needs a `WrapTarget` (outer cage). `WrapLayer.Order` controls stacking (shirt under jacket).
- Non-R15 targets can receive layered accessories if they have a WrapTarget cage.
- Studio's **Accessory Fitting Tool** creates/configures accessories; the **Calisthenics tool** previews deformation.
- Classic 2D `Shirt`/`Pants` (585×559 template) still work on R15 and are the cheapest uniform system for NPCs.

### 12.6 HumanoidDescription and avatar scaling

`HumanoidDescription` holds body part IDs, colours, accessories, clothing, animations, and scales: `HeightScale`, `WidthScale`, `HeadScale`, `DepthScale`, `BodyTypeScale`, `ProportionScale`.

```lua
-- Server: apply a team outfit while keeping the player's body and face.
local Players = game:GetService("Players")

local TEAM_TINT = Color3.fromHex("3FA7D6")

local function applyOutfit(player: Player)
	local character = player.Character or player.CharacterAdded:Wait()
	local humanoid = character:WaitForChild("Humanoid") :: Humanoid
	local desc = humanoid:GetAppliedDescription()  -- always start from the current one
	desc.Shirt = 0                                  -- set your own uploaded Shirt asset id here
	desc.TorsoColor = TEAM_TINT
	desc.HeightScale = math.clamp(desc.HeightScale, 0.95, 1.05) -- normalize hitbox height
	local ok, err = pcall(function()
		humanoid:ApplyDescriptionAsync(desc)
	end)
	if not ok then warn("ApplyDescriptionAsync failed:", err) end
end

Players.PlayerAdded:Connect(function(p)
	p.CharacterAppearanceLoaded:Connect(function() applyOutfit(p) end)
end)
```

- `Humanoid:ApplyDescription()` and `Players:CreateHumanoidModelFromDescription()` are **deprecated** — use the `…Async` versions.
- `Player:LoadCharacterWithHumanoidDescription(desc)` to spawn with an outfit (requires `Players.CharacterAutoLoads` handling).
- `HumanoidDescription:SetAccessories(list, includeRigid)` for layered/bulk accessory edits.
- Don't mix manual instance edits (adding meshes to the character) with `ApplyDescription` — undefined behaviour.
- Scaling: R15 characters also expose `BodyHeightScale`/`BodyWidthScale`/`BodyDepthScale`/`HeadScale`/`BodyTypeScale`/`BodyProportionScale` `NumberValue`s under the Humanoid (with `Humanoid.AutomaticScalingEnabled`); prefer HumanoidDescription. Game Settings ▸ Avatar can clamp ranges for fairness.

### 12.7 NPC creation

| Approach | Code | Pros |
|---|---|---|
| From description | `Players:CreateHumanoidModelFromDescriptionAsync(desc, Enum.HumanoidRigType.R15)` | Full avatar fidelity, wears catalog/your items, uses default animations once you add an Animate script |
| From user | `Players:CreateHumanoidModelFromUserIdAsync(userId)` | Instant "real looking" NPC (only use IDs you have rights to show — e.g., your own or the player's) |
| Rig Builder | Studio Avatar ▸ Rig Builder → block/mesh R15/R6 rig | Quick blank NPC to dress |
| Custom mesh NPC | skinned FBX + `AnimationController` + `Animator` (no Humanoid) | Cheapest for crowds/monsters; Humanoid is expensive at scale |

```lua
-- Spawn a styled villager NPC from a HumanoidDescription (server).
local Players = game:GetService("Players")

local function makeVillager(cf: CFrame, skin: Color3, shirtId: number?, pantsId: number?): Model
	local d = Instance.new("HumanoidDescription")
	for _, prop in { "HeadColor", "TorsoColor", "LeftArmColor", "RightArmColor", "LeftLegColor", "RightLegColor" } do
		(d :: any)[prop] = skin
	end
	if shirtId then d.Shirt = shirtId end
	if pantsId then d.Pants = pantsId end
	d.HeightScale, d.WidthScale = 1, 1
	local npc = Players:CreateHumanoidModelFromDescriptionAsync(d, Enum.HumanoidRigType.R15)
	npc.Name = "Villager"
	local hum = npc:FindFirstChildOfClass("Humanoid") :: Humanoid
	hum.DisplayDistanceType = Enum.HumanoidDisplayDistanceType.None
	npc:PivotTo(cf)
	npc.Parent = workspace
	return npc
end
```

Performance: > ~30 Humanoid NPCs near a player gets expensive (state machine, physics). Anchor idle NPCs' HRP, disable unneeded `HumanoidStateType`s with `SetStateEnabled`, stream them, and play animations from the client where possible.

### 12.8 Character customization systems (game-side)

- Store choices as **data** (palette index, hair asset id, outfit preset) in DataStores — not instances.
- Rebuild the look with one `ApplyDescriptionAsync` call per change; debounce rapid UI clicks.
- Previews: `ViewportFrame` + `WorldModel` with a cloned rig, or `Players:CreateHumanoidModelFromDescriptionAsync` client-side for the preview.
- Selling items: only your own uploaded or Marketplace items; `AvatarEditorService` can prompt saving outfits / purchasing catalog items with consent.
- In-experience avatar creation (`AvatarCreationService`) lets players publish creations — advanced; see `avatar/in-experience-creation.md`.
